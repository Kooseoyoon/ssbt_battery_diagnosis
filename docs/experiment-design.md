## 0\. 선행 검증 결과: 팩 성능 지표 정의가 G1 게이트를 좌우한다

설계에 들어가기 전, 기존 G1 게이트 결과(4.14%)가 왜 작게 나왔는지 확인했다. **원인은 데이터가 아니라 팩 성능 지표 정의였다.**

보유 C matrix(85×35, second-life 1\~206 사이클)로 지표 3종을 비교:

|지표|정의|4S|8S|16S|
|-|-|-|-|-|
|**A** (기존)|고정 윈도우 누적 `Σ\_t min\_i C\_i(t)`, t=1..35|2.09%|4.38%|5.63%|
|**B**|EOL 도달 시점 `min{t : min\_i C\_i(t) < thr}`|21.4%|55.3%|96.0%|
|**C**|EOL까지 누적 `Σ\_{t<T\_eol} min\_i C\_i(t)`|21.2%|55.6%|97.1%|

(thr = 1.60 Ah, 전체 85셀 균등분할, Oracle 정렬키 = 윈도우 평균용량)

**Oracle 정렬키를 목표함수에 정합시키면 (셀별 EOL 시점으로 정렬)** 지표 C 기준:

|팩 구성|Current|Oracle|**Oracle gain**|
|-|-|-|-|
|4S1P|106.0|175.6|**65.7%**|
|8S1P|78.9|170.6|**116.3%**|
|16S1P|35.3|97.8|**176.8%**|

몬테카를로 1000회 랜덤 재고 샘플링, thr 민감도(1.50/1.60/1.70 Ah) 확인. thr=1.60에서 p5 기준으로도 4S 14.0% / 8S 40.7% / 16S 81.8%로 전부 양수.

### 왜 이렇게 달라지는가

지표 A는 **용량의 절대 수준이 값을 지배한다.** 셀 간 초기 용량 CV가 1.4%에 불과하므로, 열화 차이는 큰 기저값 위의 작은 섭동으로 묻힌다. 2\~6%는 "개선 여지가 없다"가 아니라 "지표가 개선 여지를 보지 못한다"는 뜻이었다.

지표 B/C는 **재사용 팩의 실제 가치 구조와 일치한다.** 직렬 팩은 가장 약한 셀이 EOL에 도달하는 순간 끝난다. 즉 수명이 긴 셀과 짧은 셀을 같은 팩에 넣는 것이 손실의 핵심 원천이고, Oracle은 바로 그것을 피한다.

결정적 근거: **Spearman(초기 용량, 셀 EOL 도달 시점) = 0.275.** 현재 용량은 "언제 죽을지"를 거의 예측하지 못한다. 반면 Spearman(초기, 최종 용량) = 0.467이었다. 즉 **용량 수준보다 수명이 훨씬 예측하기 어렵고, 그래서 개선 여지도 수명 쪽에 있다.**

> ⚠️ 위 수치는 206사이클 절단 데이터 기준이다. 전 구간 재전처리 후 절대값은 바뀐다. 방향성(지표 B/C ≫ 지표 A, 팩 크기에 따라 단조 증가)은 임계값·샘플링에 걸쳐 견고하다.

### 설계에 반영할 결정

* **주 지표를 C로 확정** (EOL까지 누적 가용 용량). 지표 B는 보조(해석 용이), 지표 A는 기존 결과와의 연결용으로만 보고.
* Oracle은 **목표함수와 정합한 정렬키**를 사용한다. 평균용량 정렬 Oracle은 진짜 상한이 아니다.
* EOL 임계값 `thr`은 민감도 분석 대상으로 두고, 주 결과는 nominal 2.4 Ah 기준 SOH 60%(=1.44 Ah)로 고정 제안. (second-life 시작이 80% SOH이므로 80→60% 구간이 재사용 운용 구간)

## Stage 1 — G1 게이트 (개선 여지 정량화)

### 입력

`C\_full.npz`, `T\_eol.npy`, `censor\_mask.npy`

### 계산

**팩 성능 함수** (직렬 nS1P, 지표 C):

```
m(t) = min\_{i ∈ pack} C\_i(t)
T\_eol(pack) = min{ t : m(t) < thr }
V(pack) = Σ\_{t < T\_eol(pack)} m(t)
```

**두 조립 전략**

* `V\_current`: 진단 시점 용량(= second-life 1사이클 용량)만으로 정렬 후 균등 분할
* `V\_oracle`: 전 궤적을 알고 **목표함수를 직접 최적화**. 균등분할 휴리스틱이 아니라, 셀별 `T\_eol`로 정렬한 뒤 분할하고, 추가로 local swap 개선을 수렴까지 적용

**변수**: 팩 크기 n ∈ {4, 8, 12, 16}, thr ∈ {SOH 55%, 60%, 65%}, 재고 크기 ∈ {32, 64, 85}

**반복**: 재고를 랜덤 샘플링해 1000회

### 산출물

`g1\_gate.csv`

|컬럼|내용|
|-|-|
|`pack\_size`|4 / 8 / 12 / 16|
|`thr\_soh`|0.55 / 0.60 / 0.65|
|`inventory\_size`|32 / 64 / 85|
|`V\_current\_mean`, `V\_oracle\_mean`|평균 팩 성능|
|`oracle\_gain\_mean`, `\_p5`, `\_p50`, `\_p95`|gain 분포|
|`worst\_pack\_gain\_mean`|최악 팩 개선도 (하위 성능 위험 지표)|
|`censored\_pack\_frac`|우측 절단 팩 비율|

### 통과 기준

`oracle\_gain\_p5 > 10%`가 최소 하나의 (pack\_size, thr) 조합에서 성립. 현재 예비 결과로는 충분히 통과할 전망.

### 부수 산출물 (제안서 figure 1)

팩 크기 vs Oracle gain 곡선. "대형 팩일수록 정밀 진단의 가치가 크다"는 핵심 주장의 근거.

## Stage 3 — 확률적 궤적 예측 모델

### 입력

`features.npz` (예산 n\_i까지), 타깃은 `C\_full`의 n\_i 이후 구간

### 출력 형식 요구사항

점추정이 아니라 **궤적의 사후 분포**. Stage 5의 EVOI 계산이 샘플링을 요구하기 때문이다.

출력: 셀 i에 대해 S개의 궤적 샘플 `{C\_i^(s)(t)}\_{s=1..S}`, S = 200\~500

### 모델 후보 (단순 → 복잡)

|모델|불확실성 획득 방식|비고|
|-|-|-|
|Gaussian Process (용량 궤적에 대해)|사후 분산 직접|85셀 규모에 적합. **1차 선택 권장**|
|Quantile regression (LightGBM 등)|분위수 앙상블|가볍고 강건|
|Deep ensemble / MC dropout LSTM|앙상블 분산|데이터 85셀로는 과적합 위험|
|반경험 열화식 + 파라미터 사후분포|Bayesian 파라미터 추정|해석성 우수, 외삽 안정|

> 85셀은 딥러닝에 작다. \*\*GP 또는 반경험식 + 베이지안 파라미터\*\*로 시작하고, 복잡한 모델은 성능이 부족할 때만 올리는 순서가 안전하다. iMOE 논문 코드를 baseline으로 쓸 수 있다.

### 교차검증 설계 (중요)

85셀로 "모델 학습"과 "팩 재고"를 동시에 해야 하므로 누출 방지가 필수다.

```
외부 5-fold: 85셀 → train 68 / test 17
  - 궤적 예측 모델은 train 68셀로만 학습
  - 팩 조립 시뮬레이션의 재고는 test 17셀만 사용
  - 재고 17셀로는 4S 4팩 / 8S 2팩 구성 → 팩 수가 부족
```

**대안 (권장)**: 반복 분할을 늘린다. `train 60 / test 25`로 20회 반복 랜덤 분할하면 test 25셀에서 4S 6팩 / 8S 3팩을 구성할 수 있고, 반복으로 분산을 잡는다. 또는 **Stage 2의 외부 데이터셋(TPSL 77셀, UL 130셀)으로 모델을 학습**하고 Deep Sorting 85셀 전체를 재고로 쓰는 구조가 가장 깔끔하다.

### 산출물

|산출물|형식|shape|
|-|-|-|
|`posterior\_samples.npz`|궤적 사후 샘플|(n\_split, 85, N\_budget, S, T\_horizon)|
|`pred\_metrics.csv`|예측 성능|RMSE, MAE, 분위수 보정(calibration: PIT/PICP), CRPS — 예산별|

### 검증

**보정(calibration)이 핵심이다.** 90% 예측구간이 실제로 90%를 포함하는가(PICP ≈ 0.9)? 보정이 안 된 사후분포로는 EVOI가 무의미하다. 보정 실패 시 conformal prediction으로 후처리한다.

## Stage 4 — 팩 조립 최적화

### 입력

`posterior\_samples.npz` (현재 정보 기준 사후분포)

### 계산

재고 N셀 → n셀씩 K팩 구성. 조립의 기대 가치:

```
A\* = argmax\_A  E\_{C \~ posterior} \[ Σ\_{k=1..K} V(A\_k, C) ]
```

기댓값은 S개 샘플 평균으로 근사. 조합 최적화이므로 완전탐색 불가 → 휴리스틱:

1. **초기해**: 예측 `T\_eol` 중앙값으로 정렬 후 균등 분할
2. **개선**: 두 팩 간 셀 쌍 교환(2-swap)으로 기대가치가 증가하면 수용. 수렴까지 반복
3. (선택) simulated annealing으로 국소최적 탈출

### 산출물

|산출물|형식|shape|
|-|-|-|
|`assignment.npy`|팩 할당|(n\_split, N\_budget, N\_cells) → 팩 인덱스|
|`expected\_value.npy`|조립의 기대 팩 가치|(n\_split, N\_budget)|

### 검증

Oracle 조립(Stage 1)을 상한으로, 랜덤 조립을 하한으로 두고 그 사이에 들어오는지 확인.

## Stage 5 — 적응형 진단: 어떤 셀을 더 검사할 것인가

**제안서 STEP 3의 "기대 손실을 가장 크게 줄여줄 셀"을 여기서 계산 가능한 형태로 정의한다.**

### 입력

현재 상태 `s = (n\_1, ..., n\_N)` (셀별 누적 진단량), 각 셀의 사후분포

### 목적함수: Expected Value of Information

셀 j를 Δ사이클 더 진단하면 새 관측 `d\_j`를 얻는다. `d\_j`는 현재 사후분포로부터 시뮬레이션한다.

```
EVOI(j) = E\_{d\_j \~ p(·|D\_j)} \[ max\_A E\_{C \~ p(·|D, d\_j)}\[V(A,C)] ]
          - max\_A E\_{C \~ p(·|D)}\[V(A,C)]
```

**획득 기준** (비용 정규화):

```
j\* = argmax\_j  EVOI(j) / Δ
```

### 몬테카를로 구현

```
for each candidate cell j:
    EVOI\_j = 0
    for r = 1..R:                      # R = 20\~50 (외부 샘플)
        d\_j^(r) \~ p(d\_j | D\_j)         # 사후분포에서 가상 관측 생성
        posterior\_j ← 사후분포 갱신 (셀 j만)
        A\_r ← Stage 4 조립 최적화 (갱신된 사후분포로)
        EVOI\_j += E\_{C\~posterior'}\[V(A\_r, C)] / R
    EVOI\_j -= 현재 기대가치
```

계산량: N셀 × R외부샘플 × S내부샘플 × 조립최적화. 85 × 30 × 200 = 51만 회 평가 + 조립. **무겁다.**

### 경량 대체 지표 (권장: 먼저 이것으로 검증)

**결정 전환 빈도 (Decision Flip Frequency, DFF)**

```
S개 궤적 샘플 각각에 대해 조립 최적화를 독립 수행 → S개 할당 A^(1..S)
DFF(j) = 셀 j의 팩 배정이 샘플 간에 달라지는 비율
```

* 계산량이 EVOI의 1/R로 줄어든다
* 직관: 샘플에 따라 배정이 흔들리는 셀 = 정보가 부족해서 결정이 불안정한 셀 = 더 진단할 가치가 있는 셀
* **"단순히 가장 불확실한 셀이 아니다"는 제안서 5절 주장을 그대로 구현한다.** 용량 예측 분산이 커도 팩 배정이 안 바뀌면 DFF는 낮다

> 전략: DFF로 전체 파이프라인을 먼저 완성하고, 여력이 있으면 EVOI를 추가해 DFF가 EVOI의 좋은 근사인지 비교한다. 이 비교 자체가 기여가 된다.

### 진단 스케줄

```
while 예산 남음 and 중단조건 미충족:
    j\* = argmax\_j DFF(j) (또는 EVOI(j)/Δ)
    셀 j\*를 Δ사이클 추가 진단 (= 실제 데이터를 Δ만큼 더 공개)
    셀 j\*의 사후분포 갱신
    기록: (step, j\*, n\_{j\*}, 총예산, 현재 기대가치, 추정 regret)
```

### 산출물

|산출물|형식|내용|
|-|-|-|
|`diagnosis\_log.csv`|step별 로그|step, selected\_cell, delta, cumulative\_budget, expected\_value, estimated\_regret, DFF\_max, EVOI\_max|
|`allocation.npy`|최종 셀별 진단량|(n\_split, N\_cells)|

### 검증

진단량 배분이 **불균등**해야 한다. 균등하게 나오면 선택 기준이 작동하지 않는 것이다. 히스토그램으로 집중도(Gini 계수 등) 보고.

## Stage 6 — 조기 중단 규칙

### 중단 조건 (3안, 비교 대상)

|안|조건|성격|
|-|-|-|
|**S1** 한계가치|`max\_j EVOI(j) / Δ < λ · (사이클당 진단비용)`|경제적으로 정당|
|**S2** regret 상한|추정 regret의 상위 분위수 `< ε`|보수적, 보증 지향|
|**S3** 결정 안정화|전체 DFF가 임계치 미만 + m step 연속 할당 불변|계산 저렴|

### 추정 regret (중단 시점에 계산 가능한 값)

실제 regret은 미래를 알아야 하므로 중단 시점엔 모른다. 대신:

```
estimated\_regret = E\_{C\~posterior}\[ max\_A V(A,C) ] - E\_{C\~posterior}\[ V(A\*,C) ]
```

(샘플별 사후최적 조립의 평균 − 현재 단일 조립의 기대가치)

이것이 실제 regret의 **하향 편향 추정치**가 되므로, 보정 계수나 conformal 보정을 적용해 상한을 만든다.

### 산출물

`stopping.csv` — 규칙별 중단 시점 예산, 추정 regret, **실제 regret**(숨겨둔 미래로 사후 평가), 실패 여부(실제 regret > ε)

### 검증 (제안서 7.3)

**조기 중단 실패율** = `P(실제 regret > ε | 중단)`. 목표: 10% 미만. 이것이 규칙의 신뢰성 지표다.

### 최종 주장 문장의 형태

제안서 6절의 목표("진단량 30% 절감, regret 5% 이하")는 다음 형태로 치환해 서술한다.

> 전수 정밀 진단 대비 진단량 \*\*X%\*\* 수준에서 pack regret \*\*Y%\*\* 를 달성했고, 동일 regret을 Uniform 배분으로 달성하려면 \*\*Z%\*\* 의 진단량이 필요했다. 즉 선택적 진단으로 \*\*(Z−X)/Z\*\* 의 진단량을 절감했다.

이 형태는 절대 수치를 미리 약속하지 않으면서도 비교 우위를 명확히 주장한다.
