────────────────────────────────────────────────────────────
무엇을 하는 코드인가
────────────────────────────────────────────────────────────
pack.py 는 채점기입니다. 셀을 어떻게 묶었는지 주면 그 배정의
점수를 냅니다. 직렬 팩의 수명은 가장 먼저 죽는 셀이 정하므로,
매 측정 지점에서 팩 안 최솟값을 구해 임계값 아래로 내려가기
전까지 더하고 5를 곱합니다. 미사용 셀은 0으로 칩니다.
상한(upper_bound)도 들어 있어 탐색이 얼마나 잘했는지 가늠할
수 있습니다.

search.py 는 탐색기입니다. 86셀을 8개씩 묶는 경우의 수가
천문학적이라 전수 조사가 불가능하므로, 여러 시작점에서 출발해
두 셀을 바꿔치며 점수가 오르는 방향으로 올라갑니다. 국소
최적에 갇히면 SA 로 빠져나옵니다. 바꿔치기는 팩끼리뿐 아니라
팩과 미사용 사이에서도 일어나므로, 어느 셀을 안 쓸지도 탐색이
스스로 정합니다.

────────────────────────────────────────────────────────────
미사용 셀 규칙 (9가지 변경 반영분)
────────────────────────────────────────────────────────────
배정 = P = floor(N/n) 개 팩 + 미사용 셀.
라벨 배열에서 미사용은 -1 이고 V 에 0 을 기여합니다.
어느 셀을 안 쓸지도 각 방식이 스스로 정합니다.

반영한 항목
  1. 배정 정의와 -1 표현                     pack.py
  2. 팩<->미사용 교환, SA 도 같은 이웃        search.py
  3. sorted_start 가 상위 P*n 만 묶음         search.py
  5. upper_bound 가 상위 P*n 만 사용          pack.py
  8. 미사용 관련 테스트 2개                   tests/

이 묶음 밖 (stage1_exhaustive.py, stage1_g1.py 에서 처리)
  4. Current-only 배정
  6. 전수 검사 문제 2개 추가
  7. 재고 부분집합 규칙
  9. 출력 열 이름

────────────────────────────────────────────────────────────
받는 사람이 알아야 할 것
────────────────────────────────────────────────────────────
1. 목적함수 서명
   objective(cells) -> float, 즉 팩 하나의 값입니다.
   배정 전체를 받는 형태로 바꾸면 증분 평가가 불가능해져
   탐색이 수십 배 느려집니다. Stage 4 의 시나리오 평균도
   팩 단위로 분해되므로 문제없습니다.
   Stage 1 은 PackScorer(C, n_i, thr).pack 을 넘기면 됩니다.

2. configs/search.yaml 은 아직 임시값입니다
   SA 설정은 stage1_exhaustive.py 로 전수 검사를 돌린 뒤
   거기서 고른 값으로 덮어써야 합니다.
   sa_iters_per_neighbour 는 null 로 두었습니다. 미사용이 있는
   문제만 놓친 폭이 크게 나오면 그때 켜는 스위치입니다.

3. numba 는 넣지 않았습니다
   PackScorer 로 22배 빨라져 86셀 한 조건이 약 55초에
   끝납니다. 계획서의 "numba = 순수 파이썬" 비교는
   "PackScorer = 기존 경로" 비교로 대체했습니다.
   전수 검사에서 느리면 그때 붙이면 됩니다.

4. 검열값 주의
   sorted_start 에 넘기는 점수에 -1 이 섞이면 그 셀이 가장
   나쁜 셀로 취급돼 미사용으로 밀립니다. 실제로는 끝까지 안
   죽은 가장 좋은 셀입니다. EOL 60% 에서는 검열 셀이 없어
   지금은 문제가 없지만, 55%/65% 나 LFP 데이터에서는 걸립니다.
   stage1_g1.py 에서 T_eol 을 넘기기 전에 -1 을 +inf 로
   바꿔 주십시오.

5. 재현성
   best_of(..., seed=N) 의 N 하나면 전체가 재현됩니다.
   SearchResult.seed 에 그 값이 남고, log_rows() 가
   search_log.csv 에 넣을 시작점별 기록을 돌려줍니다.
